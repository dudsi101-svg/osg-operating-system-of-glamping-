## P0 proof rule

A valid scenario seed is not the same as a concurrency/invariant proof.

Schema v1.0 FINAL requires executable validation defined in:
- `../tests/specs/OSG_P0_Proof_Execution_Plan_v0.1.md`
- GitHub Issues #1–#5, #8 and #9

Current critical proof families:
- temporal StaySegment overlap,
- Resource capacity concurrency,
- atomic Financial Truth posting + immutable posted facts,
- tenant isolation (DB/API/background jobs),
- idempotent integrations/automations,
- same-tenant cross-Property context integrity,
- clean-load all schema/patches/semantic objects/scenarios.

## Runtime roles / RLS

RLS must be tested using a realistic application DB role. PostgreSQL table owners/superusers may bypass RLS. Do not declare tenant-isolation proof successful when tests run only as owner/superuser.

## IDs

Canonical business entity IDs are UUIDv7 generated by the application/shared ID layer (ADR-007). Deterministic fixture IDs in seeds are only test/reference IDs.

## Promotion rule

After executable P0 proofs pass:
1. fold accepted v0.96–v0.99 patches into canonical v1.0 DDL,
2. reconcile duplicated/replaced helper/trigger definitions,
3. create actual versioned migrations,
4. rerun clean DB + upgrade-path tests,
5. pin Semantic Layer v1 metric contracts,
6. tag/checkpoint Schema v1.0 FINAL candidate.
