# Model danych

Ten katalog będzie zawierał kanoniczne specyfikacje encji, relacji, kardynalności, cykli życia i ograniczeń integralności OSG.

## Zakres

- Organization & Identity
- Property Graph
- Guest, Commerce & Stay
- Experience
- Operations & Maintenance
- Financial Truth
- Integration, Audit & Intelligence

## Zasady

- Model biznesowy powstaje przed schematem SQL.
- Każda encja ma jasno opisane znaczenie i właściciela źródła prawdy.
- Dane pochodne są oznaczone jako projekcje.
- Relacje między tenantami są zabronione.
- Fakty historyczne i finansowe muszą być audytowalne.
